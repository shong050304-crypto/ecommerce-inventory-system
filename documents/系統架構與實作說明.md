# 電商訂單與庫存管理系統 — 架構設計與實作說明

> 建立日期：2026-05-17  
> 資料庫系統：MySQL 8.0+  
> 編碼：UTF-8 (utf8mb4)

---

## 一、專案概述

本系統為一個**電商訂單與庫存管理系統**，目標是建立一套完整的關聯式資料庫，涵蓋：

- 會員管理
- 商品分類與商品管理
- 訂單處理（含明細）
- 庫存異動追蹤

> 本系統嚴格依據資料庫計劃書的需求分析，以及 ERD 圖與 Schema 圖進行設計，確保所有實體、屬性與關係皆完整對應。共包含 **6 個實體**、**5 組關聯關係**。

## 二、系統架構總覽

### 2.1 資料庫實體關聯模型

**資料表關係：**

```
MEMBERS ──(1:N)──> ORDERS ──(1:N)──> ORDER_DETAILS <──(1:N)── PRODUCTS
                                                                  |
CATEGORIES ──(1:N)──> PRODUCTS                                    |
                         |                                        |
                         └──(1:N)──> INVENTORY_LOGS              |
```

### 2.2 資料表欄位總覽

#### MEMBERS（會員資料表）
| 欄位 | 型態 | 約束 | 說明 |
|------|------|------|------|
| member_id | INT | PK, AUTO_INCREMENT | 會員ID |
| name | VARCHAR(50) | NOT NULL | 姓名 |
| email | VARCHAR(100) | NOT NULL, UNIQUE | 電子郵件 |
| password_hash | VARCHAR(255) | NOT NULL | 密碼雜湊值 |
| phone | VARCHAR(20) | UNIQUE | 聯絡電話 |
| address | VARCHAR(255) | | 送貨地址 |
| created_at | DATETIME | NOT NULL, DEFAULT NOW | 註冊時間 |

#### CATEGORIES（商品分類表）
| 欄位 | 型態 | 約束 | 說明 |
|------|------|------|------|
| category_id | INT | PK, AUTO_INCREMENT | 分類ID |
| name | VARCHAR(50) | NOT NULL, UNIQUE | 分類名稱 |
| description | VARCHAR(255) | | 分類描述 |

#### PRODUCTS（商品資料表）
| 欄位 | 型態 | 約束 | 說明 |
|------|------|------|------|
| product_id | INT | PK, AUTO_INCREMENT | 商品ID |
| category_id | INT | FK → CATEGORIES, NOT NULL | 分類ID |
| name | VARCHAR(100) | NOT NULL | 商品名稱 |
| price | DECIMAL(10,2) | NOT NULL, CHECK > 0 | 售價 |
| stock_quantity | INT | NOT NULL, DEFAULT 0, CHECK >= 0 | 庫存量 |
| description | TEXT | | 商品描述 |
| is_active | BOOLEAN | NOT NULL, DEFAULT TRUE | 上架狀態 |

#### ORDERS（訂單資料表）
| 欄位 | 型態 | 約束 | 說明 |
|------|------|------|------|
| order_id | INT | PK, AUTO_INCREMENT | 訂單ID |
| member_id | INT | FK → MEMBERS, NOT NULL | 會員ID |
| total_amount | DECIMAL(12,2) | NOT NULL, DEFAULT 0, CHECK >= 0 | 訂單總額 |
| payment_status | VARCHAR(20) | NOT NULL, CHECK IN(...) | 付款狀態 |
| order_status | VARCHAR(20) | NOT NULL, CHECK IN(...) | 訂單狀態 |
| cancel_reason | VARCHAR(255) | | 取消原因 |
| created_at | DATETIME | NOT NULL, DEFAULT NOW | 建立時間 |

**付款狀態值域：** `未付款`、`已付款`、`失敗`

**訂單狀態值域：** `處理中`、`已出貨`、`已完成`、`申請取消`、`已取消`

#### ORDER_DETAILS（訂單明細表）
| 欄位 | 型態 | 約束 | 說明 |
|------|------|------|------|
| detail_id | INT | PK, AUTO_INCREMENT | 明細ID |
| order_id | INT | FK → ORDERS, NOT NULL | 訂單ID |
| product_id | INT | FK → PRODUCTS, NOT NULL | 商品ID |
| quantity | INT | NOT NULL, CHECK > 0 | 購買數量 |
| unit_price | DECIMAL(10,2) | NOT NULL, CHECK > 0 | 結帳單價 |
| subtotal | DECIMAL(12,2) | NOT NULL, CHECK > 0 | 小計金額 |

> 唯一約束：`(order_id, product_id)` — 同一訂單中不可重複出現相同商品
>
> 設計考量：紀錄結帳當下的「單價」，避免未來商品調價時影響歷史訂單的金額計算（適度的反正規化）。

#### INVENTORY_LOGS（庫存異動記錄表）
| 欄位 | 型態 | 約束 | 說明 |
|------|------|------|------|
| log_id | INT | PK, AUTO_INCREMENT | 紀錄ID |
| product_id | INT | FK → PRODUCTS, NOT NULL | 商品ID |
| change_quantity | INT | NOT NULL, CHECK != 0 | 變動數量 |
| change_type | VARCHAR(20) | NOT NULL, CHECK IN(...) | 變動類型 |
| created_at | DATETIME | NOT NULL, DEFAULT NOW | 紀錄時間 |

**變動類型值域：** `進貨`、`訂單扣減`、`取消退回`、`庫存調整`

### 2.3 資料表關係摘要

| 關係 | 類型 | 說明 |
|------|------|------|
| MEMBERS → ORDERS | 1:N | 一位會員可下多筆訂單（會員「下單」產生訂單） |
| CATEGORIES → PRODUCTS | 1:N | 一個分類包含多個商品（分類「包含」商品） |
| ORDERS → ORDER_DETAILS | 1:N | 一筆訂單記載多筆明細（訂單「記載」訂單明細） |
| PRODUCTS → ORDER_DETAILS | 1:N | 一個商品可被列入多筆明細（商品被「列入」訂單明細） |
| PRODUCTS → INVENTORY_LOGS | 1:N | 一個商品產生多筆庫存記錄（商品異動「產生」庫存紀錄） |

> **注意：** ORDER_DETAILS 是 ORDERS 與 PRODUCTS 之間多對多 (N:M) 關係的中介表，解決了訂單與商品的多對多問題。

### 2.4 參與度與基數分析

| 關聯 | 端 | 限制 | 說明 |
|------|-----|------|------|
| 會員「下單」訂單 | 會員端 | (0, N) | 選擇性參與，可有 0~N 筆訂單 |
| | 訂單端 | (1, 1) | 強制參與，每筆訂單必屬 1 位會員 |
| 分類「包含」商品 | 分類端 | (0, N) | 選擇性參與，可包含 0~N 個商品 |
| | 商品端 | (1, 1) | 強制參與，每個商品必屬 1 個分類 |
| 訂單「記載」明細 | 訂單端 | (1, N) | 強制參與，至少 1 筆明細 |
| | 明細端 | (1, 1) | 強制參與，每筆明細必屬 1 筆訂單 |
| 商品「列入」明細 | 商品端 | (0, N) | 選擇性參與，可出現在 0~N 筆明細 |
| | 明細端 | (1, 1) | 強制參與，每筆明細對應 1 個商品 |
| 商品「產生」庫存紀錄 | 商品端 | (0, N) | 選擇性參與，可有 0~N 筆紀錄 |
| | 紀錄端 | (1, 1) | 強制參與，每筆紀錄對應 1 個商品 |

## 三、約束與索引設計

### 3.1 約束 (Constraints) 設計

| 約束類型 | 適用表 | 說明 |
|----------|--------|------|
| **PRIMARY KEY** | 所有表 | 每張表皆有自增主鍵 |
| **FOREIGN KEY** | PRODUCTS, ORDERS, ORDER_DETAILS, INVENTORY_LOGS | 確保參照完整性 |
| **UNIQUE** | MEMBERS(email, phone), CATEGORIES(name) | 防止重複資料 |
| **CHECK** | PRODUCTS(price > 0, stock >= 0), ORDERS(status 值域), ORDER_DETAILS(qty > 0) | 確保資料合理性 |
| **NOT NULL** | 各表關鍵欄位 | 防止必要欄位為空 |
| **DEFAULT** | created_at, is_active, stock_quantity | 簡化插入操作 |

### 3.2 索引 (Index) 設計

| 索引名稱 | 資料表 | 欄位 | 用途 |
|----------|--------|------|------|
| idx_products_category | PRODUCTS | category_id | 加速按分類查詢商品 |
| idx_products_is_active | PRODUCTS | is_active | 加速篩選上架商品 |
| idx_orders_member | ORDERS | member_id | 加速查詢會員訂單 |
| idx_orders_status | ORDERS | order_status | 加速按狀態篩選訂單 |
| idx_orders_payment | ORDERS | payment_status | 加速按付款狀態篩選 |
| idx_orders_created | ORDERS | created_at | 加速按日期排序 |
| idx_order_details_order | ORDER_DETAILS | order_id | 加速查詢訂單明細 |
| idx_order_details_product | ORDER_DETAILS | product_id | 加速按商品查詢銷售記錄 |
| idx_inventory_logs_product | INVENTORY_LOGS | product_id | 加速查詢商品庫存記錄 |
| idx_inventory_logs_type | INVENTORY_LOGS | change_type | 加速按類型篩選 |
| idx_inventory_logs_created | INVENTORY_LOGS | created_at | 加速按時間排序 |

### 3.3 訂單狀態流程

```
[新訂單] → 處理中 → 已出貨 → 已完成
```

### 3.4 付款狀態流程

```
[建立訂單] → 未付款 → 已付款
                ↓
              失敗
```

## 五、觸發器與預存程序

### 5.1 觸發器 (Triggers)

| 觸發器名稱 | 觸發時機 | 功能說明 |
|------------|----------|----------|
| `trg_after_order_detail_insert` | ORDER_DETAILS INSERT 後 | 自動重新計算訂單總金額 |
| `trg_after_order_detail_delete` | ORDER_DETAILS DELETE 後 | 自動重新計算訂單總金額 |
| `trg_after_inventory_log_insert` | INVENTORY_LOGS INSERT 後 | 自動更新商品庫存量 |

> **設計原則：** 庫存更新統一由 `trg_after_inventory_log_insert` 觸發器處理，預存程序不再手動更新庫存，避免重複計算（double-counting）問題。

### 5.2 預存程序 (Stored Procedures)

| 程序名稱 | 功能說明 | 參數 |
|----------|----------|------|
| `sp_create_order` | 建立新訂單（含庫存檢查、扣減、Transaction） | IN: member_id, product_id, quantity; OUT: order_id, result_message |
| `sp_get_member_orders` | 查詢指定會員的訂單歷史 | IN: member_id |
| `sp_restock_product` | 庫存補貨 | IN: product_id, quantity; OUT: result_message |

### 5.3 訂單建立流程（Transaction 保護）

```
開始建立訂單
    ├─ 檢查商品是否存在且上架中
    │    └─ 否 → 回傳錯誤：商品不存在或已下架
    ├─ 檢查庫存是否足夠
    │    └─ 否 → 回傳錯誤：庫存不足
    └─ 是 → START TRANSACTION
              ├─ INSERT INTO ORDERS（建立訂單）
              ├─ INSERT INTO ORDER_DETAILS（建立明細）
              ├─ INSERT INTO INVENTORY_LOGS（記錄異動，觸發器自動扣減庫存）
              └─ COMMIT → 回傳成功訊息
```

## 七、核心查詢功能

### 04_queries.sql 包含以下查詢：

1. **訂單還原查詢** — 多表 JOIN（MEMBERS + ORDERS + ORDER_DETAILS + PRODUCTS）
2. **即時庫存查詢** — 含庫存狀態標示（正常/低庫存/缺貨）
3. **特定商品庫存變動歷程** — 追蹤進出貨紀錄
4. **各會員消費總額排行** — GROUP BY + SUM/COUNT/AVG
5. **各分類銷售統計** — LEFT JOIN + 聚合函數
6. **商品銷售排行榜 TOP 10** — 排名統計
7. **月度銷售趨勢分析** — DATE_FORMAT + GROUP BY
8. **訂單狀態分佈** — 多維度交叉統計
9. **高消費會員篩選** — 子查詢 + AVG 比較
10. **訂單總覽視圖** — CREATE VIEW

## 九、注意事項

- 執行 `01_create_database.sql` 會**刪除並重建**資料庫，請勿在正式環境使用
- 密碼使用 SHA2-256 雜湊，正式環境建議使用 bcrypt
- 觸發器可能影響批量操作效能，正式環境需評估
- `sp_create_order` 使用 `FOR UPDATE` 行級鎖防止 Race Condition
- 確保 MySQL 的 `STRICT_TRANS_TABLES` 模式已啟用，以確保 CHECK 約束生效
- 庫存更新統一由觸發器處理，預存程序不應直接修改 `stock_quantity`
