# 電商訂單與庫存管理系統 — 系統更新日誌 (Changelog)

本文件詳細記錄了本專案在對接實體資料庫、修復環境執行腳本、改善使用者體驗（UX）及強化資料一致性等方面所進行的重大功能更新與代碼重構。

---

## 📅 版本更新摘要 - 2026年5月

本次更新之核心目標為**「全面移除 Mock 虛擬資料，完美對接 Flask 後端 API 與 MySQL 資料庫，並修復環境啟動腳本」**，確保系統具備商業級的實體連線、高併發安全庫存處理與高穩定的啟動能力。

---

## 🛠️ 詳細更新項目

### 1. 全面移除 Mock 虛擬資料與對接實體 API
* **前端重構**：
  * 徹底刪除了前端原有的模擬資料夾 `frontend/src/data` (包含 `mockData.js`)。
  * 刪除了原有的 LocalStorage 模擬資料庫 [dataStore.js](file:///c:/NKNU/Sophomore%20second%20semester/Database/Assignment/期末資料庫設計專題報告/電商訂單與庫存管理系統/frontend/src/services/dataStore.js)。
  * 將商品加載、商品分類、訂單建立（下單）、後台統計、商品 CRUD 等所有元件之資料來源，改為實體呼叫 Flask 後端提供的 API 服務。
* **資料持久化**：
  * 除了購物車草稿（`ecommerce_cart`）與登入身分權限 Token（`ecommerce_current_user` / `ecommerce_admin`）暫存在前端瀏覽器的 `localStorage` 之外，所有核心商業資料一律改為實體儲存於 MySQL 資料庫中。

### 2. 修復與優化 Windows 環境啟動腳本 (.bat)
* **主啟動腳本 (`run.bat`)**：
  * **問題修正**：原先使用 `start cmd /c` 時，若專案路徑中含有空格或特殊字元，會造成 Windows 的 Cmd 發生引號剝離（Quote stripping）解析錯誤進而閃退。
  * **優化方案**：改用 `cmd /k` 搭配雙重雙引號 `""%~dp0...""`，並在新視窗中啟動前後端，解決了空格路徑閃退問題，且啟動失敗時視窗會保留，方便除錯。
* **後端啟動腳本 (`run_backend.bat`)**：
  * **問題修正**：在 `if-else` 的批次檔語法中，原先有 `echo (venv)` 指令。然而 Windows 批次檔解譯器會將右括號 `)` 誤判為 `if` 程式區塊的結束，導致後續啟動 Flask 的 Python 指令直接被跳過而無法開啟後端。
  * **優化方案**：改用中括號 `echo [venv]`，成功排除批次檔解析錯誤，讓 Flask 後端能順利在虛擬環境中被啟動。
* **路徑切換優化**：
  * 在 `run_frontend.bat` 與 `run_backend.bat` 中的 `cd` 改用 `cd /d`，確保即使專案存放在不同磁碟機（例如 D 槽或 E 槽），也能成功跨磁碟切換至正確路徑。

### 3. 優化前端異常處理與使用者體驗 (UX)
* **新增異常捕捉 (Catch-error)**：
  * 在 [ProductsPage.jsx](file:///c:/NKNU/Sophomore%20second%20semester/Database/Assignment/期末資料庫設計專題報告/電商訂單與庫存管理系統/frontend/src/pages/products/ProductsPage.jsx) 與 [AdminProductsPage.jsx](file:///c:/NKNU/Sophomore%20second%20semester/Database/Assignment/期末資料庫設計專題報告/電商訂單與庫存管理系統/frontend/src/pages/admin/products/AdminProductsPage.jsx) 等關鍵介面中，加入了 fetch API 的錯誤捕捉功能。
  * **效果**：當後端 Flask 伺服器未啟動或資料庫斷線時，網頁不再是無反應的空白頁，而是會主動顯示「無法載入商品，請確認後端伺服器已啟動！」的紅框警示，極大提升了系統的強健性與使用者體驗。

### 4. 新增資料庫「訂單快速查詢工具」
為了讓開發者或期末評審不用每次都進入 MySQL Command Line 或是管理軟體輸入複雜的 JOIN 語法，本版本特地新增了內建的一鍵查詢工具：
* **`run_check_orders.bat` (根目錄)**：雙擊即可快速執行。
* **`backend/check_orders.py`**：會自動連接本機 MySQL 資料庫，自動載入環境設定，並以精美的格式列出最近的 10 筆訂單、購買人資訊、購買商品明細、單價、小計與訂單狀態。

### 5. 資料一致性與庫存併發安全加固
* **防止併發超賣 (Over-selling)**：
  * 在下單事務的資料庫處理中，後端 API 採取 `SELECT ... FOR UPDATE` 行級鎖定（Row Lock），在訂單尚未 Commit 提交前，鎖定商品當前庫存，防止高併發下庫存資料失準。
* **資料庫 Transaction（事務）**：
  * 將「檢查庫存」、「新增訂單主表」、「新增訂單明細」與「寫入庫存異動日誌」打包在同一個資料庫連接的事務（Transaction）中，只要其中一步出錯（如庫存不足），自動進行 `rollback` 回滾，維持 ACID 原則。
* **庫存異動觸發器同步**：
  * 連接了資料庫的 `trg_after_inventory_log_insert` 觸發器。每一次下訂單在 `INVENTORY_LOGS` 寫入扣減日誌時，觸發器會自動去更新 `PRODUCTS` 中的當前剩餘庫存，實現了「單一入口更新庫存」的防錯設計。
