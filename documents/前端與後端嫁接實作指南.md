# 前端與後端嫁接實作指南

本指南旨在協助前端開發組員將原有的 **LocalStorage / Mock 數據層**（位於 `frontend/src/services/dataStore.js` 及各 Mock API 函式中）平滑遷移並嫁接至由 **Flask API 後端 + MySQL 資料庫** 組成的實體系統中。

後端實作已遵循 [API契約.md](file:///c:/NKNU/Sophomore%20second%20semester/Database/Assignment/%E6%9C%9F%E6%9C%AB%E8%B3%87%E6%96%99%E5%BA%AB%E8%A8%AD%E8%A8%88%E5%B0%88%E9%A1%8C%E5%A0%B1%E5%91%8A/%E9%9B%BB%E5%95%86%E8%A8%82%E5%96%AE%E8%88%87%E5%BA%AB%E5%AD%98%E7%AE%A1%E7%90%86%E7%B3%BB%E7%B5%B1/documents/API%E5%A5%91%E7%B4%84.md) 的 API 規範。以下為具體的嫁接與改寫步驟。

---

## 1. 系統環境與連線設定

### 1.1 前端環境變數
前端需要建立或修改位於 `frontend/.env` 的環境變數，以設定實體後端 API 的 Base URL。
```env
VITE_API_URL=http://localhost:3000/api
```
在 React (Vite) 中，可透過 `import.meta.env.VITE_API_URL` 進行讀取。

### 1.2 CORS 設定
後端 Flask 服務運行於 `http://localhost:3000`，已啟用 CORS 並允許 `http://localhost:5173`（前端 Vite 預設 Port）的跨來源存取。

## 2. 認證與狀態管理 (JWT Token)

本系統全面使用 **JWT (JSON Web Token)** 作為使用者與管理員的身份驗證機制。

### 2.1 儲存 Token
在登入或註冊成功後，後端會回傳一個加密的 `token`。前端需將其持久化儲存於 `localStorage` 中：

```javascript
// 會員登入成功後
localStorage.setItem('member_token', responseData.token);
localStorage.setItem('member_user', JSON.stringify(responseData.user));

// 管理員登入成功後
localStorage.setItem('admin_token', responseData.token);
```

### 2.2 攜帶 Token 於請求標頭 (Header)
對於需要認證的 API（如建立訂單、查詢歷史訂單、所有管理端操作等），前端必須在 HTTP Request Headers 中帶上 `Authorization` 欄位：

```javascript
const token = localStorage.getItem('member_token'); // 或 admin_token

const headers = {
  'Content-Type': 'application/json',
  'Authorization': `Bearer ${token}`
};
```

## 3. 狀態值映射對照表 (Enum Mapping)

為了與 MySQL 資料庫中的約束 (CHECK Constraint) 保持一致，系統採取「**前端英文傳輸，後端進行中文轉換，資料庫中文儲存**」的策略：

| 欄位名稱 | API 傳輸值 (前端) | 資料庫儲存值 (DB) | 說明 |
|---|---|---|---|
| **付款狀態** `payment_status` | `unpaid` <br> `paid` <br> `failed` | `未付款` <br> `已付款` <br> `失敗` | 訂單建立預設為 `unpaid` |
| **訂單狀態** `order_status` | `processing` <br> `shipped` <br> `completed` | `處理中` <br> `已出貨` <br> `已完成` | 訂單建立預設為 `processing` |
| **異動類型** `change_type` | `purchase` <br> `order_deduct` <br> `cancel_return` | `進貨` <br> `訂單扣減` <br> `取消退回` | 供庫存日誌使用 |

> [!NOTE]
> 後端在接收到前端請求時會自動將狀態值轉為中文寫入資料庫；在回傳資料給前端時，會自動將中文轉回對應的英文狀態。前端組員無須於頁面進行轉換，僅需依原有的英文狀態處理邏輯即可。

## 4. 會員端 API 嫁接改寫範例

請更新 [api.js](file:///c:/NKNU/Sophomore%20second%20semester/Database/Assignment/%E6%9C%9F%E6%9C%AB%E8%B3%87%E6%96%99%E5%BA%AB%E8%A8%AD%E8%A8%88%E5%B0%88%E9%A1%8C%E5%A0%B1%E5%91%8A/%E9%9B%BB%E5%95%86%E8%A8%82%E5%96%AE%E8%88%87%E5%BA%AB%E5%AD%98%E7%AE%A1%E7%90%86%E7%B3%BB%E7%B5%B1/frontend/src/services/api.js)，將對 Mock / LocalStorage 的操作改為實體 HTTP `fetch` 呼叫：

### 4.1 會員登入 (Login)
```javascript
// 舊的 Mock 寫法：
// export async function login(email, password) { ... }

// 新的實體 API 寫法：
export async function login(email, password) {
  const response = await fetch(`${BASE_URL}/auth/login`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ email, password }),
  });

  const resData = await response.json();
  if (!response.ok) {
    throw new Error(resData.error?.message || '登入失敗');
  }
  
  // 儲存 Token 與使用者資訊
  localStorage.setItem('member_token', resData.token);
  localStorage.setItem('member_user', JSON.stringify(resData.user));
  return resData.user;
}
```

### 4.2 建立訂單 (Create Order)
建立訂單需要攜帶身份 Token，且參數需轉換為 snake_case（與後端/資料庫對齊）：
```javascript
// 新的實體 API 寫法：
export async function createOrder({ items, address, phone }) {
  const token = localStorage.getItem('member_token');
  
  const response = await fetch(`${BASE_URL}/orders`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${token}`
    },
    body: JSON.stringify({
      items: items.map(i => ({
        product_id: i.productId,
        quantity: i.quantity
      })),
      shipping_address: address,
      shipping_phone: phone
    }),
  });

  const resData = await response.json();
  if (!response.ok) {
    throw new Error(resData.error?.message || '訂單建立失敗');
  }
  return resData;
}
```

### 4.3 獲取會員歷史訂單 (Fetch Orders)
```javascript

  const response = await fetch(`${BASE_URL}/orders`, {
```

## 6. 前端串接除錯與檢查點

1. **JWT 驗證失效 (401 Unauthorized)**：
   * 請確認 `Authorization` Header 的格式為 `"Bearer <Token>"`，注意 `Bearer` 與 Token 之間有一個半形空格。
   * 請確認在調用需要權限的 API 前，Token 已正確從儲存區中讀取，且 Token 並未過期（預設有效期限為 24 小時）。
2. **錯誤訊息顯示**：
   * 後端所有的商業邏輯拒絕或錯誤都會統一格式化為 `{"error": {"code": "代碼", "message": "錯誤訊息"}}`。
   * 前端應使用 `error.message` 來提示使用者（例如庫存不足、Email 已被註冊等）。
3. **CORS 阻擋**：
   * 若於瀏覽器開發者工具 (F12) 的 Console 中看見 CORS 錯誤，請確認後端已正確載入 `.env` 中的設定，且前端的請求來源與後端的允許清單一致。
